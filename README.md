# IRS Generator

`irs-generator` - Python-библиотека для моделирования инерциальной
навигационной системы (IRS/INS) и потокового синтеза идеальных данных IMU и
GNSS по заранее подготовленной целевой траектории.

Проект ориентирован на воспроизводимые инженерные расчёты, исследование
алгоритмов навигации и создание синтетических наборов данных. Внутренние
вычисления выполняются в СИ; преобразование к внешним форматам вынесено на
границу ввода-вывода.

> Статус: ранняя версия API. Ядро Earth/INS и потоковый генератор покрыты
> тестами, однако интерфейсы могут уточняться до первого стабильного релиза.

## Глоссарий

| Термин | Расшифровка и значение в проекте |
| --- | --- |
| **API** | *Application Programming Interface* — публичный программный интерфейс: классы и функции, которые пользователь библиотеки может импортировать и вызывать. |
| **CSV** | *Comma-Separated Values* — текстовый табличный формат. В проекте разделитель настраивается и не обязан быть запятой. |
| **DCM** | *Direction Cosine Matrix* — матрица направляющих косинусов, то есть матрица поворота между системами координат. Текущая механизация хранит ориентацию как DCM «корпус → навигационная система». |
| **ENU** | *East–North–Up* — локальная навигационная система: восток, север, вверх. В ней представлены скорость, сила и навигационные скорости вращения. |
| **GNSS** | *Global Navigation Satellite System* — общее название спутниковых навигационных систем, включая GPS, ГЛОНАСС, Galileo и BeiDou. В контексте проекта GNSS-данные могут быть измерением для коррекции INS либо траекторией истины. |
| **GPS** | *Global Positioning System* — американская спутниковая система; имя сохраняется в файле `gps.dat` как часть внешнего DAT-контракта. |
| **IMU** | *Inertial Measurement Unit* — инерциальный измерительный модуль: акселерометры и гироскопы. Его выход — удельная сила и угловая скорость в системе корпуса. |
| **INS** | *Inertial Navigation System* — инерциальная навигационная система: алгоритм, который интегрирует данные IMU и вычисляет положение, скорость и ориентацию. |
| **IRS** | *Inertial Reference System* — инерциальная опорная система. В проекте это композиция навигационного алгоритма INS и модели ошибок IMU. |
| **DAT-формат** | Внешний формат `imu.dat` и `gps.dat` с фиксированными заголовками и единицами. |
| **Poisson kinematics** | Кинематическое уравнение Пуассона для изменения ориентации при известной угловой скорости. В текущей реализации оно интегрируется через операции на SO(3). |
| **SO(3)** | *Special Orthogonal Group in 3D* — множество корректных трёхмерных матриц поворота: ортогональных матриц с определителем `+1`. |
| **Strapdown-механизация** | Способ навигационных вычислений, при котором IMU жёстко закреплена на объекте, а её измерения непрерывно интегрируются в цифровом алгоритме. |
| **Удельная сила** | Ускорение, измеряемое акселерометром: кинематическое ускорение без гравитационного ускорения. Единица — m/s². |
| **Механизация INS** | Конкретные уравнения и численный метод распространения состояния INS по измерению IMU: ориентации, скорости и положения. |
| **Траектория истины** | Заданная безошибочная траектория, используемая как эталон для синтеза или оценки. В генераторе она определяет требуемую скорость и ориентацию. |
| **Обратный решатель** | Численный алгоритм, который подбирает вход IMU для одного шага так, чтобы выбранная механизация INS достигла целевого состояния. |
| **Потоковая обработка** | Обработка данных по одной записи за раз без загрузки всей траектории в оперативную память. |
| **`fork()`** | Операция создания независимой копии текущего состояния алгоритма. Нужна генератору для пробных численных шагов без изменения основной траектории. |
| **WGS 84 / GRS 80** | Стандартные референц-эллипсоиды Земли и связанные с ними геодезические параметры. |

## Возможности

- модели Земли WGS 84, GRS 80 и настраиваемая сферическая модель;
- нормальная гравитация Сомильяны, центральная обратноквадратичная и постоянная
  гравитация;
- страпдаун-механизация в локальной ENU-системе координат;
- текущая реализация навигационного алгоритма: `DcmStrapdownINS` — матрица
  направляющих косинусов (DCM) и кинематика Пуассона на группе SO(3);
- расширяемый контракт навигационного алгоритма: будущие реализации на
  кватернионах или другой механизации можно подключать к генератору без его
  переписывания;
- модель IRS как композиция навигационного алгоритма и модели ошибок IMU;
- потоковое чтение подготовленной траектории и запись результатов: объём
  входного файла не удерживается в памяти;
- точный DCM-генератор `DcmTrajectoryGenerator`, который вычисляет идеальные
  IMU-измерения напрямую из соседних точек траектории;
- численный обратный решатель, подбирающий показания IMU так, чтобы выбранный
  алгоритм INS достигал заданных скорости и ориентации на следующем шаге;
- готовый профиль `DatOutputFormat` для файлов `imu.dat` и `gps.dat` и
  настраиваемый `CsvOutputFormat`.

## Принятые соглашения

### Системы координат

Навигационная система — **ENU**:

- `x` — восток (East);
- `y` — север (North);
- `z` — вверх (Up).

Связанная с корпусом система:

- `x_body` — вправо;
- `y_body` — вперёд;
- `z_body` — вверх.

Скорость представляется как `(east, north, up)`. Углы ориентации хранятся в
полях `(pitch, roll, heading)` и интерпретируются той же DCM-конвенцией, что
использует `DcmStrapdownINS`.

### Единицы

В доменной модели используются исключительно единицы СИ:

| Величина | Внутренняя единица |
| --- | --- |
| время | s |
| координаты | rad, m |
| скорость | m/s |
| удельная сила | m/s² |
| угловая скорость | rad/s |

`DatOutputFormat` выполняет требуемые DAT-форматом преобразования:
широта и долгота записываются в градусах, угловые скорости — в градусах в
секунду. В generic CSV-профиле единицы можно выбрать явно.

### Численная точность

Внутренний численный scalar-контракт проекта основан на `np.longdouble`.
Валидация чисел, базовые value-классы, векторы, модели Земли, гравитация,
механизация INS и генераторы не приводят значения к обычному Python `float`
без необходимости.

Есть несколько осознанных границ `float64`:

- сравнение с эталонными DAT-файлами выполняется в ULP `float64`, потому что
  сами файлы являются текстовым представлением double-значений;
- `numpy.linalg` на части платформ не поддерживает `longdouble` для SVD и
  решения линейных систем, поэтому эти операции явно выполняются через
  `float64`, а результат возвращается в общий longdouble-контракт.

Важно: реальная точность `np.longdouble` зависит от платформы и сборки NumPy.
На некоторых Windows-сборках он совпадает с `float64` по мантиссе. Проект всё
равно использует `np.longdouble` как единый внутренний контракт, чтобы код не
терял точность там, где платформа предоставляет расширенный тип.

## Архитектура

```text
irs_generator/
├── earth_model/        # геометрия Земли, вращение и гравитация
├── navigation_model/   # неизменяемые состояние, скорость и ориентация
├── gps_model/          # контракт измерения GNSS
├── irs_model/          # IMU, ошибки, механизация и IRS
├── generation/         # потоковый синтез IMU/GNSS и CSV-адаптеры
└── utils/              # небольшие математические и валидационные примитивы
```

Важная граница ответственности:

- `NavigationAlgorithm` описывает минимальный алгоритм для обычного IRS:
  состояние, `reset()` и `step()`;
- `InertialNavigationAlgorithm` расширяет его методом `fork()`. Он требуется
  генератору, чтобы выполнять пробные численные шаги, не изменяя рабочее
  состояние алгоритма;
- `InertialReferenceSystem` применяет модель ошибок к идеальному измерению IMU
  перед передачей в навигационный алгоритм;
- `DcmTrajectoryGenerator` — основной точный режим синтеза для DCM-траекторий;
- `SyntheticDataGenerator` работает с произвольным чистым алгоритмом INS и не
  выполняет коррекцию по GNSS: файл GNSS в этом сценарии является траекторией
  истины.

## Установка

Требуется Python 3.12 или новее.

Поддерживаются два способа работы с окружением: `uv` и стандартные `venv` +
`pip`. Для одного клона репозитория используйте только один из них: не следует
смешивать `uv sync` и ручные вызовы `pip install` в одном `.venv`.

### Использование опубликованной библиотеки

После публикации на PyPI библиотеку можно установить через `pip`:

```bash
pip install irs-generator
```

или через `uv` в проект-потребитель:

```bash
uv add irs-generator
```

Обе команды получают один и тот же пакет `irs-generator` из PyPI. Разница в
том, что `uv add` дополнительно записывает зависимость в `pyproject.toml`
проекта-потребителя и обновляет его `uv.lock`, а `pip install` устанавливает
пакет в активное окружение. Для разовой установки через `uv` без изменения
файлов проекта используйте:

```bash
uv pip install irs-generator
```

### Рекомендуемый путь разработки: uv

`uv` создаёт и синхронизирует проектное окружение `.venv` по
`pyproject.toml` и `uv.lock`.

```bash
uv sync --extra test --extra lint
```

Команды запускаются через синхронизированное окружение:

```bash
uv run pytest
uv run ruff check .
uv run mypy src tests
```

Для CI и других воспроизводимых сред, где lock-файл не должен изменяться:

```bash
uv sync --frozen --extra test --extra lint
```

### Разработка через стандартные venv и pip

Создайте проектное виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
source .venv/bin/activate
```

Установите библиотеку в редактируемом режиме вместе с инструментами разработки:

```bash
python -m pip install --upgrade pip
python -m pip install -e ".[test,lint]"
```

## Быстрый старт: распространение состояния INS

```python
from irs_generator.earth_model import GeodeticPosition
from irs_generator.irs_model import DcmStrapdownINS, ImuSample
from irs_generator.navigation_model import (
    EulerAngles,
    NavigationState,
    NavigationVelocity,
)

initial_state = NavigationState(
    velocity=NavigationVelocity(0.0, 0.0, 0.0),
    position=GeodeticPosition(
        longitude_rad=0.65,
        latitude_rad=0.96,
        height_m=150.0,
    ),
    attitude=EulerAngles(pitch_rad=0.0, roll_rad=0.0, heading_rad=0.0),
)

ins = DcmStrapdownINS(initial_state)
state = ins.step(ImuSample.zero(), dt_s=0.01)
```

`ImuSample.zero()` — нулевое измерение, а не состояние покоя на Земле: при
таком входе вертикальная скорость будет изменяться под действием гравитации.
Для моделирования неподвижного прибора нужно подать соответствующую удельную
силу и угловую скорость.

## Генерация чистых IMU и GNSS-данных

Генератор принимает последовательность `TargetTrajectoryPoint`. Первая точка
обязана содержать начальную геодезическую позицию; у последующих точек позиция
не требуется. Алгоритм INS распространяет её самостоятельно, сохраняя
согласованность выходных данных IMU и GNSS.

```python
from pathlib import Path

from irs_generator.generation import (
    CsvOutputWriter,
    CsvTrajectoryReader,
    SyntheticDataGenerator,
)
from irs_generator.irs_model import DcmStrapdownINS
from irs_generator.navigation_model import NavigationState

points = CsvTrajectoryReader("prepared_trajectory.csv")
first_point = next(iter(points))
assert first_point.position is not None

initial_state = NavigationState(
    velocity=first_point.velocity,
    position=first_point.position,
    attitude=first_point.attitude,
)
generator = SyntheticDataGenerator(DcmStrapdownINS(initial_state))

# Читатель и генератор потоковые: строки не собираются в полный список.
with CsvOutputWriter(Path("output")) as writer:
    for step in generator.generate(CsvTrajectoryReader("prepared_trajectory.csv")):
        writer.write(step)
```

В примере первая строка считывается только для создания начального состояния;
затем читатель создаётся заново. Это корректно и сохраняет потоковую модель.
В прикладном коде также можно создать начальное состояние из известных
параметров, не выполняя предварительного чтения файла.

### Полный пример полёта

В [examples/full_flight](examples/full_flight) находится реальная
подготовленная траектория на 45 997 точек, эталонные файлы IMU и GNSS и
исполняемый потоковый пример. Набор одновременно служит документацией,
демонстрационными данными и интеграционной проверкой точности.

```bash
# Короткая проверка первых 100 точек.
python examples/full_flight/generate.py --points 100

# Полный сценарий; результат появится в examples/full_flight/output/.
python examples/full_flight/generate.py
```

### Работа с демонстрационными данными через pandas

Полный набор можно использовать как воспроизводимый пример, аналогично
встроенным наборам данных pandas: прочитать траекторию, сгенерировать выход и
исследовать результат как `DataFrame`.

```python
from pathlib import Path

import pandas as pd

from irs_generator.generation import (
    DcmTrajectoryGenerator,
    DcmTrajectoryReader,
)

example_dir = Path("examples/full_flight")
input_path = example_dir / "input" / "prepared_trajectory.csv"
output_dir = example_dir / "output"

trajectory = pd.read_csv(input_path)
print(trajectory.head())

reader = DcmTrajectoryReader(input_path)
generator = DcmTrajectoryGenerator(time_step_s=reader.time_step_s())
generator.write(reader, output_dir)

imu = pd.read_csv(output_dir / "imu.dat", sep=r"\s+")
gnss = pd.read_csv(output_dir / "gps.dat", sep=r"\s+")
print(imu.head())
print(gnss.head())
```

`DcmTrajectoryReader` и `DcmTrajectoryGenerator` — точный DCM-путь для
канонической подготовленной траектории. Для произвольных форматов и новых
механизаций INS используйте `CsvTrajectoryReader` и `SyntheticDataGenerator`.

### Входная траектория CSV

`CsvTrajectoryReader` по умолчанию ожидает заголовки:

```text
t_meas_s,lat_deg,lon_deg,alt_m,pitch_rad,roll_rad,heading_rad,v_e_mps,v_n_mps,v_u_mps
```

Только в первой строке обязательны `lat_deg`, `lon_deg`, `alt_m`. В следующих
строках их можно оставить пустыми. Время должно строго возрастать; по
умолчанию также проверяется равномерность шага. Другие имена столбцов или
неравномерную временную сетку можно задать через `CsvTrajectorySchema`.

### Выходные файлы

По умолчанию `CsvOutputWriter` использует `DatOutputFormat` и создаёт:

- `imu.dat`: `Time Ax Ay Az Wx Wy Wz`;
- `gps.dat`: `T Lat Lon Hsns Ve Vn SNS_GOOD Shassi`.

Для другого потребителя задайте `CsvOutputFormat`:

```python
from irs_generator.generation import CsvOutputFormat, CsvOutputWriter

profile = CsvOutputFormat(
    delimiter=";",
    imu_filename="imu.csv",
    gps_filename="gps.csv",
    angular_rate_unit="rad/s",
    geographic_angle_unit="rad",
)

with CsvOutputWriter("output", format=profile) as writer:
    ...
```

## Расширение навигационным алгоритмом

Чтобы подключить новую механизацию, например кватернионную, реализуйте
`InertialNavigationAlgorithm`:

```python
from irs_generator.gps_model import GnssSample
from irs_generator.irs_model import ImuSample
from irs_generator.navigation_model import NavigationState


class QuaternionIns:
    @property
    def state(self) -> NavigationState: ...

    def reset(self, initial_state: NavigationState) -> None: ...

    def fork(self) -> "QuaternionIns":
        # Вернуть независимую копию, включая всё изменяемое внутреннее состояние.
        ...

    def step(
        self,
        imu_sample: ImuSample,
        dt_s: float,
        gnss_sample: GnssSample | None = None,
    ) -> NavigationState: ...
```

Именно `fork()` обеспечивает, что конечный численный решатель может безопасно
использовать алгоритм в итерационном цикле. Реализация должна возвращать
глубоко независимую копию изменяемого состояния.

## Ограничения текущей версии

- Реализован только DCM-вариант страпдаун-механизации; кватернионная
  механизация пока является точкой расширения.
- Генератор синтезирует идеальные данные. Интеграция ошибок IMU в генератор,
  модели приёмника GNSS и шумовые сценарии — следующий отдельный слой.
- Нет CLI: библиотека предназначена для вызова из Python-кода. Командный
  интерфейс следует добавлять как тонкий адаптер поверх публичного API.
- Генератор не выполняет GNSS-коррекцию в цикле синтеза: это осознанно,
  поскольку его цель — построение самосогласованной чистой траектории.
